Why this solution is optimal

1 · State space is complete

A trip is a walk of at most K+1 flights. Whatever the history, the future cost depends only on (current city, flights used, coupons used). Tracking exactly these three numbers loses no information, so DP over them is exact.

2 · Induction over layers

Layer 0 holds only (city 1, 0 coupons) at cost 0. If layer t stores the true minimum cost for every (city, coupons) reachable in t flights, then layer t+1 is built by relaxing every outgoing flight with both choices (full fare, or ⌊p/2⌋ if a coupon is left). Any cheapest (t+1)-flight walk has a cheapest t-flight prefix (otherwise swap it for a cheaper one), so layer t+1 is also exact. The answer is the minimum over layers 1…K+1 at city N.

3 · Why plain Dijkstra on cities or a greedy coupon rule fails

Cheapest path ≠ cheapest path within K+1 flights, and the best coupon placement can change which path wins (a pricier path with one huge fare can beat the cheap path once halved). Concrete trap: flights 1→2 (30), 2→3 (30), 1→3 (80), K=1, C=1. Greedy takes the 60-fare path and halves one leg: 45. Optimal is the direct flight with the coupon: 40. Greedy can also return −1 when its cheapest path needs more flights than K+1 allows. The stress test above counts how often it is wrong.

4 · Why coupons never need “saving”

⌊p/2⌋ ≤ p, so spending a coupon never raises the cost. The DP still tracks the exact count because a coupon can be used only once per flight and at most C times overall, and the best flight for a coupon depends on the route.

5 · Complexity

Layered DP: O((K+1)(C+1)(N+M)) time, O((K+1)N(C+1)) space (parent table). Dijkstra on expanded states adds a log factor for the heap. Brute force is O((2M)^(K+1)), exponential in K.

Corner-case suite

Every case is run through DP, Dijkstra and brute force, and the returned route is independently re-validated (connected walk, ≤ K+1 flights, ≤ C coupons, cost recomputed).
